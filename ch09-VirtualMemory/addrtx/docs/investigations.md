# Phase 0 - Virtual Address Investigation

Objective

Observe virtual addresses generated by:

- Global variables
- Heap allocations
- Stack variables

Questions

1. Why are addresses different?
2. Why is the stack near the top of memory?
3. Why are heap allocations close together?
4. What part of the address identifies the page?

# Phase 0 - Virtual Address Investigation

## Test Program

Observed addresses from the same process:

```text
global      : 0x5dcf3a1ce010
heap object : 0x5dcf46d92010
heap ptr    : 0x7ffc144c4350
stack       : 0x7ffc144c434c
```

## Findings

### Heap Object vs Heap Pointer

Heap object:

```text
0x5dcf46d92010
```

Pointer variable:

```text
0x7ffc144c4350
```

The allocated object resides in heap memory,
while the pointer variable itself resides in the
stack frame.

### Stack Layout

Observed:

```text
heap ptr : 0x7ffc144c4350
stack    : 0x7ffc144c434c
```

These addresses are adjacent because both
variables are stored in the same stack frame.

### Process Memory Layout

Observed:

```text
global      : 0x5dcf...
heap object : 0x5dcf...
stack       : 0x7ffc...
```

This suggests the traditional Linux process
layout:

```text
High Addresses
+------------------+
| Stack            |
+------------------+

| Shared Libraries |

+------------------+
| Heap             |
+------------------+
| Globals / Data   |
+------------------+
| Text Segment     |
+------------------+
Low Addresses
```

## Key Learning

A pointer and the object it references may reside
in completely different regions of virtual memory.

# Phase 1 - VPN + Offset Split

## Observed Translations

Global Variable

```text
Address : 0x583fe86bf010
VPN     : 0x583fe86bf
Offset  : 0x10
```

Heap Object

```text
Address : 0x584002347010
VPN     : 0x584002347
Offset  : 0x10
```

Heap Pointer

```text
Address : 0x7ffee7a54270
VPN     : 0x7ffee7a54
Offset  : 0x270
```

Stack Variable

```text
Address : 0x7ffee7a5426c
VPN     : 0x7ffee7a54
Offset  : 0x26c
```

## Findings

Heap pointer and stack variable share the same:

```text
VPN
```

meaning they reside within the same memory page.

Heap object resides in a completely different
virtual page.

## Key Learning

A virtual address consists of:

```text
Virtual Page Number (VPN)
+
Page Offset
```

The VPN identifies the page.

The offset identifies the position within
that page.

# Phase 2 - Binary Visualization

## Example

Input

```text
0x600e0c861010
```

Output

```text
VPN     : 0x600e0c861
Offset  : 0x10
```

Binary Layout

```text
VPN (52 bits)

0000000000000000011000000000111000001100100001100001

Offset (12 bits)

000000010000
```

Visual Split

```text
|<-------VPN------>|<-OFFSET->|

011000000000111000001100100001100001|000000010000
```

## Findings

The final 12 bits represent the page offset.

```text
000000010000
```

equals:

```text
0x10
```

The remaining bits form the VPN.

## Key Learning

Virtual memory translation operates on:

```text
VPN
```

The offset passes through unchanged during
translation.

# Phase 3 - Address Classification

## Observed Addresses

Global

```text
0x6089e489f010
```

Heap Object

```text
0x608a1cd1a010
```

Heap Pointer

```text
0x7ffc007b9640
```

Stack Variable

```text
0x7ffc007b963c
```

## Classification Results

```text
0x6089e489f010  -> HEAP_DATA
0x608a1cd1a010  -> HEAP_DATA

0x7ffc007b9640  -> STACK
0x7ffc007b963c  -> STACK
```

## Findings

Heap pointer and stack variable share:

```text
VPN = 0x7ffc007b9
```

and therefore reside in the same virtual page.

Heap object resides in a different virtual page
and is classified as HEAP_DATA.

## Key Learning

An address is not only:

```text
VPN + Offset
```

It also belongs to a virtual memory region:

```text
Stack
Heap
Data
```

These regions form the process address space.

# Phase 4 - Page Size Explorer

## Address

```text
0x61d34150f010
```

### 4 KB Pages

```text
Offset Bits : 12

VPN         : 0x61d34150f
Offset      : 0x10
```

### 2 MB Pages

```text
Offset Bits : 21

VPN         : 0x30e9a0a
Offset      : 0x10f010
```

### 1 GB Pages

```text
Offset Bits : 30

VPN         : 0x1874d
Offset      : 0x150f010
```

## Findings

Increasing page size increases the number of
offset bits.

As a result:

```text
VPN Space Decreases
Offset Space Increases
```

Large pages cover larger memory regions and
require fewer page translations.

## Key Learning

Huge pages reduce:

- Page table size
- TLB pressure
- Translation overhead

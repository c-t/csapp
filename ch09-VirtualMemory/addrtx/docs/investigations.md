# Phase 0 - Virtual Address Investigation

Objective

Observe virtual addresses generated by:

- Global variables
- Heap allocations
- Stack variables

Questions

1. Why are addresses different?
2. Why is the stack near the top of memory?
3. Why are heap allocations close together?
4. What part of the address identifies the page?

# Phase 0 - Virtual Address Investigation

## Test Program

Observed addresses from the same process:

```text
global      : 0x5dcf3a1ce010
heap object : 0x5dcf46d92010
heap ptr    : 0x7ffc144c4350
stack       : 0x7ffc144c434c
```

## Findings

### Heap Object vs Heap Pointer

Heap object:

```text
0x5dcf46d92010
```

Pointer variable:

```text
0x7ffc144c4350
```

The allocated object resides in heap memory,
while the pointer variable itself resides in the
stack frame.

### Stack Layout

Observed:

```text
heap ptr : 0x7ffc144c4350
stack    : 0x7ffc144c434c
```

These addresses are adjacent because both
variables are stored in the same stack frame.

### Process Memory Layout

Observed:

```text
global      : 0x5dcf...
heap object : 0x5dcf...
stack       : 0x7ffc...
```

This suggests the traditional Linux process
layout:

```text
High Addresses
+------------------+
| Stack            |
+------------------+

| Shared Libraries |

+------------------+
| Heap             |
+------------------+
| Globals / Data   |
+------------------+
| Text Segment     |
+------------------+
Low Addresses
```

## Key Learning

A pointer and the object it references may reside
in completely different regions of virtual memory.

# Notes

## Phase 0 Insight

A virtual address contains enough information
to locate page-table entries at each level of
the translation hierarchy.

---

## Address Structure

```text
| PML4 | PDPT | PD | PT | OFFSET |
```

---

## Offset

```text
12 bits
```

correspond to the byte position within a page.

---

## Page-Table Levels

Each level receives:

```text
9 bits
```

which select one of:

```text
512 entries
```

within the table.

---

## Connection To AddrTx

AddrTx taught:

```text
Virtual Address
      ↓
VPN + Offset
```

PTSim will explore:

```text
VPN
 ↓
PML4
 ↓
PDPT
 ↓
PD
 ↓
PT
```

during a simulated page walk.

## Phase 1 Insight

The VPN is not stored as a single page-table
index.

Instead:

```text
VPN
 ↓

PML4
PDPT
PD
PT
```

Each level consumes:

```text
9 bits
```

of the virtual address.

The final:

```text
12 bits
```

remain the page offset.

## Phase 2 Insight

A virtual address can be viewed as a collection
of fields rather than a single number.

```text
| PML4 | PDPT | PD | PT | OFFSET |
```

The MMU extracts these fields and uses them to
navigate the page-table hierarchy.

The offset is not used during table lookup and
is carried unchanged to the final physical
address.

## Phase 3 Insight

The page-table indices extracted from a virtual
address directly correspond to positions within
page-table structures.

Example:

```text
PT Index = 227
```

means:

```text
PT[227]
```

during a page walk.

Page-table entries ultimately provide a frame
number that participates in the final address
translation.

## Phase 4 Insight

The page walk uses the virtual address as a
sequence of indices.

```text
PML4
 ↓
PDPT
 ↓
PD
 ↓
PT
 ↓
Frame
```

Each level selects an entry from a 512-entry
table.

A successful walk produces a frame number that
can later be combined with the page offset to
form a physical address.

## Phase 5 Insight

Virtual-to-physical translation does not modify
the page offset.

Example:

```text
Virtual Address

0x7ffff84e371c
          71c
```

```text
Physical Address

0x1234571c
      71c
```

The offset survives translation unchanged.

Only the page mapping changes.

## Phase 6 Insight

A page walk produces a physical frame.

Multiple virtual addresses can reference the
same frame while differing only by offsets.

Example:

```text
0x7ffff84e371c -> Frame 0x10e3

0x7ffff84e3720 -> Frame 0x10e3
```

Result:

```text
Shared Physical Frame
```

with different physical addresses generated by
different offsets.

This mirrors how real systems allow many
locations within the same page frame to be
referenced.
